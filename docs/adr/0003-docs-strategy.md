# 0003 — Docs strategy

> One source of truth. Human + AI same files. llms.txt for crawlers. Caveman for prose.

## Status

Accepted. 2026-08-24.

## Context

We're a fork of LunaSea. Solo dev + AI agents doing the bulk of edits (features, fixes, refactors, upgrades). Need a doc system that:

- Humans can browse.
- AI agents can scan fast (low tokens).
- Lives next to code, versioned in git.
- Doesn't drift.
- Doesn't bloat the repo.

## Decision

### Layout

```
docs/                       mkdocs source (Material theme)
├── index.md                30-line map. Start here.
├── build.md                APK + adb-wifi install.
├── workflow.md             Git branching + SemVer.
├── architecture.md         Big picture.
├── conventions.md          Style + commit rules.
├── troubleshooting.md      Symptom → fix.
├── features/               One .md per user-visible feature.
├── fixes/                  One .md per bug fix.
├── modules/<name>.md       Per-module living doc.
├── api/                    http, hive, routing.
├── reference/              env, gradle, codegen.
└── adr/                    Why-decisions.

AGENTS.md                   Router for all AI coding agents (Claude Code, Cursor, Codex, Copilot, Zed, ...).
.agents/
├── skills/                 Cross-tool procedural skills.
└── sessions/               Per-session handoffs (latest read first).
```

### Doc per change (mandatory)

| Change | Create |
|--------|--------|
| New feature | `docs/features/<slug>.md` |
| Bug fix | `docs/fixes/<slug>.md` |
| Module reshape | Update `docs/modules/<name>.md` |
| API / DB / route change | Update `docs/api/<area>.md` |
| Architecture decision | New ADR in `docs/adr/` |

Same PR. Conventional commit footer `Docs: <path>`.

### AI agent access

- `AGENTS.md` at root = router. Read first.
- Router maps task → doc path. Load only what matches. No "load everything".

### llms.txt

Generated by `mkdocs-llmstxt` plugin at build time. Sits at `/llms.txt` + `/llms-full.txt`. AI crawlers (external) ingest the whole site in 1 fetch. Internal agents (Claude Code) read the markdown files directly via filesystem tools — `llms.txt` is for when the site is published.

### Caveman mode

Default writing style. Short words. Tables > prose. No filler. Code > explanation.

### Session handoffs

`.agents/sessions/<YYYY-MM-DD>-<slug>.md`. Append-only. Latest = most recent work. AI agents read the latest one at session start.

### Sub-agents (superseded)

Original design used Claude Code's `.claude/agents/` sub-agent convention
(`feature-builder`, `fix-investigator`, `docs-keeper`). Removed 2026-08-26
when consolidating around the cross-tool `AGENTS.md` + `.agents/`
convention. Procedural knowledge that used to live in those sub-agents
is now in `.agents/skills/` (cross-tool) or in session handoffs under
`.agents/sessions/`.

## Consequences

### Positive

- One source of truth. No parallel "AI docs" that rot.
- Router pattern saves tokens. Agents don't load docs they don't need.
- llms.txt makes the published site AI-ingestable.
- Per-change doc = zero doc debt. Change not shipped = doc not written.
- Sub-agents = mechanical work delegated. Human stays at decisions.

### Negative

- Discipline required: every PR writes a doc. No exceptions.
- mkdocs build pipeline required for llms.txt.
- AI agent behavior depends on it reading the router. Tested empirically in AGENTS.md instruction.

### Mitigations

- Conventional Commit lint enforces `Docs:` footer for `feat` / `fix`.
- Session handoffs catch context loss if agent skipped doc step.
- `docs-keeper` sub-agent audits.

## Alternatives considered

| Option | Rejected because |
|--------|------------------|
| AICaC (`.ai/*.yaml`) | YAML discipline overhead for solo dev. Overkill. |
| SAGE `@graph` blocks in code | Requires touching every Dart file. Big refactor. Future option. |
| HADS `[SPEC]`/`[NOTE]` tags | Adds tag complexity for marginal token gain on top of caveman. |
| Separate `AGENT_NOTES.md` | Splits source of truth. Drift guaranteed. |
| No AI support | Wastes tokens every session. |
